# Retro Messenger v1.0.1 — repair notes

## Supabase 404 errors

The v1.0.0 tables `message_reactions`, `user_privacy_settings`, and
`moderation_appeals` are created by `supabase/migrations/0014_classic_social_features.sql`.
If requests to `/rest/v1/<table>` return 404, open Supabase SQL Editor and
run `supabase/verify_v1.0.0.sql`. If any table is MISSING, first apply
`0014_classic_social_features.sql` against the same Supabase project configured
in the app. This migration also installs RLS policies and RPC functions.
Do not create just the empty tables. After successful installation, run
`NOTIFY pgrst, 'reload schema';` and reload Messenger.

If tables already exist, check the REST JSON response for an error code
(e.g. `PGRST205`), the project's exposed schema/API settings, and URL.

## Update check CORS

`vercel.json` provides an `Access-Control-Allow-Origin: *` header for
`/updates.json`. The web app reads `/updates.json` from its own origin.
The Tauri desktop app reads `https://retromessenge.vercel.app/updates.json`
and needs the header on that deployed website. Redeploy the website with
`vercel --prod` after applying this update.

The release feed is read-only and public. No authenticated information is
returned. Automatic downloading and installation remain disabled until a
cryptographically signed updater is configured.

Open `https://retromessenge.vercel.app/updates.json` in a regular browser.
It should return JSON, not an authentication page or 404. If deployment
protection or a wrong domain blocks it, resolve that separately.

React DevTools text is informational. `content.js` Redirect Blocker messages
are likely from a browser extension and not a Retro Messenger source file.
